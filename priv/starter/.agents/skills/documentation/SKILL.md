# Documentation

- **Write for a reader with a task.** Say who the page is for and what they can
  do after reading it.
- **Say why, not only what.** The code already says what it does. The
  documentation says why it is shaped this way and what the alternative would
  have broken.
- **Every example runs.** An example nobody ran is a claim.
- **After a change, look for what it made untrue**: names, flags, defaults,
  paths, counts. Search for each thing the diff renamed or removed.
